# Laptop-side test nets — webOS webcam viewer

Three independent checks that run **before** anything touches the TV. They
target the known app shape (`app/index.html`, `app/js/app.js`,
`app/css/app.css`) so they work as soon as Dev lands.

Prerequisites: Node 20+, `ffmpeg` (test HLS/JPEG), `openssl` (self-signed
cert). One-time install for acorn + Playwright:

```sh
cd tools/testing && npm install
```

If Playwright's Chromium is not already cached on the machine, run
`npx playwright install chromium` once as well.

## 1. ES5 syntax gate — `es5-check.js`

```sh
node tools/testing/es5-check.js
# or: cd tools/testing && npm run es5
```

Walks `app/**/*.js` and parses every file as **strict ES5** with acorn
(`ecmaVersion: 5`). `const`, `let`, arrows, `class`, template literals,
`import`/`export`, `async`, and sloppy-only ES5 (`with`, octal literals) are
all parse errors. Prints `file:line:col` for every violation and exits `1`.

Exit codes: `0` clean, `1` syntax violations, `2` misconfigured (acorn not
installed, `app/` missing or has no JS). `WEBCAM_APP_DIR=/path/to/app`
overrides the target.

This is the highest-value check: a non-ES5 token is the bug class behind the
three earlier failed attempts on this TV.

## 2. Fake cameras — `mock-camera-server.js`

```sh
node tools/testing/mock-camera-server.js
# or: cd tools/testing && npm run mock
```

No npm dependencies. Serves:

| Endpoint | What |
|---|---|
| `http://127.0.0.1:8888/<id>/index.m3u8` | looping HLS playlist (`front`, `back`) |
| `http://127.0.0.1:8888/<id>/segN.ts` | MPEG-TS test-pattern segments, generated by ffmpeg |
| `https://127.0.0.1:8889/snap.jpeg` | static JPEG over a **self-signed** cert |
| `http://127.0.0.1:8888/app/index.html` | the app itself (or 404 if not built) |
| `http://127.0.0.1:8888/healthz` | JSON status |

The self-signed HTTPS snapshot is the point: the real cameras use
self-signed certs and webOS 4.4.3 has blocked them before. This reproduces
that locally.

**Broken-camera mode** (for reconnect/backoff): `MOCK_BROKEN=1`, append
`?broken=1` / `?fail=1`, or use the `/broken/<id>/...` path. Camera
endpoints then return 404.

Env overrides: `MOCK_HTTP_PORT` (default 8888, matches the app's hardcoded
port), `MOCK_HTTPS_PORT` (default HTTP+1), `MOCK_HOST` (default `127.0.0.1`;
use `0.0.0.0` to expose it on the LAN), `MOCK_APP_DIR` (default `<repo>/app`),
`MOCK_BROKEN=1`.

## 3. Browser smoke test — `smoke.spec.js`

```sh
cd tools/testing && npx playwright test
# or: npm test
```

Playwright starts the mock server automatically (`playwright.config.js`),
loads `/app/index.html`, and rewrites the app's hardcoded LAN camera URLs to
the mock. It asserts:

- no uncaught `pageerror`
- both tiles render
- snapshots actually load from the self-signed HTTPS mock (not just a placeholder)
- ArrowRight / ArrowLeft (`keyCode` 39 / 37) move real DOM focus between tiles
- Enter (13) opens the fullscreen player
- Back (`keyCode` 461) returns to the grid
- tiles survive camera 404s and a blocked self-signed snapshot cert

If `app/index.html` does not exist yet, the tests **skip** instead of failing.
`MOCK_APP_DIR=/path/to/app` runs them against an app in another checkout.

## What these do NOT cover

These are laptop-side nets, not a substitute for the real device.

- **Chromium 53 quirks.** Playwright's Chromium is modern; `es5-check.js`
  catches syntax, not engine behaviour (layout, media pipeline, memory).
  Rendering and HLS/MSE behaviour on the actual V8 ~5.3 engine remain
  unverified until the TV runs it.
- **webOS platform APIs.** Luna/SSAP, `webOSTV.js` (`platformBack`,
  `deviceInfo`), app lifecycle, remote-key delivery by the platform, and
  the real Back-key path are mocked or absent.
- **The real cameras and certs.** The mock reproduces self-signed HTTPS and
  HLS shape, not the cameras' actual URLs, credentials, stream profiles, or
  the TV's certificate policy.
- **Packaging/deploy.** `ares-package`/`ares-install`/`ares-launch` are not
  exercised here. `tools/deploy.sh` runs `es5-check.js` as a pre-flight.
- **Real-network conditions.** Latency, packet loss, TV Wi-Fi, and the
  logger WebSocket path are not simulated.
